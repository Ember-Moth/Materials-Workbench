## 0. 范围

**覆盖**：周期性晶体结构（含部分占位、位置无序）、空间群对称性、晶胞变换与超胞、CIF / POSCAR / 扩展 XYZ 的导入导出语义、编辑命令与撤销。

**明确不覆盖（v0.x）**：

- 磁结构（mCIF）、调制 / 非公度结构（超空间群）、大分子（mmCIF）
- 表面 / 层板（slab）构建、缺陷自动生成、有序化（SQS 等）
- ADP 编辑：导入的 ADP 完整保留、可以导出，但不提供编辑 UI
- 降到子群的对称性编辑：只支持"保持对称"和"转为 P1"两档

## 1. 设计原则

1. **对称结构是事实来源。** 结构存为"不对称单元 + 对称操作集"，P1 展开后的全部原子是派生数据。P1 结构只是操作集里只有单位元的特例，不需要第二套模型。
2. **不静默修改数据。** 吸附到特殊位置、合并重复原子、对称化、丢弃未识别的 CIF 字段，都必须产生诊断信息并告知用户。
3. **精确值保持精确。** 90°、120° 不经过弧度往返；对称操作的旋转部分是整数矩阵、平移部分是有理数；晶胞变换矩阵是有理数矩阵。
4. **结构、分析设置、视图状态分层。** 撤销只覆盖前两者，相机、配色、显示范围不进撤销栈。
5. **编辑是可序列化的命令。** 同一份命令数据同时服务于撤销重做、历史面板、来源追溯，以及将来的 Python 回放。

## 2. 分层

| 层 | 内容 | crate | 持久化 | 进撤销栈 |
|---|---|---|---|---|
| 结构模型 | 晶格、对称操作、位点、占位、容差 | `mw-crystal` | 是 | 是 |
| 派生数据 | 等效原子展开、位点对称性、Wyckoff、近邻、键、化学式 | `mw-crystal` | 否（按 revision 缓存） | — |
| 文档 | 结构 + 元数据 + 来源记录 + 分析设置（成键规则）+ 标注（测量） | `mw-crystal` 定义，`mw-project` 存储 | 是 | 是 |
| 视图状态 | 显示范围、原子半径与配色、多面体、相机 | `mw-crystal-render` | 是 | 否 |
| 会话状态 | 选区、拖拽预览、悬停 | UI | 否 | 否 |

编辑命令的定义和 apply 逻辑放在 `mw-crystal`，可以脱离 GUI 做单元测试。撤销栈目前也在 `mw-crystal`（`CrystalDocument`，见 7.12 节），它不依赖命令的具体内容；等 XRD 等第二种文档也需要撤销时，再抽成与领域无关的 `mw-command`。历史面板属于界面。

## 3. 约定

- **坐标与矩阵：列向量约定，与《国际晶体学表》A 卷一致。** 晶格矩阵 `A = [a b c]`，三列是基矢；笛卡尔坐标 `r = A·x`；对称操作 `x' = W·x + w`；度量张量 `G = Aᵀ·A`。
- **单位**：长度用 Å；模型中的角度存"度"；ADP 存 U（Å²），B 只在 IO 层换算（`U = B / 8π²`）。
- **特殊角的三角函数取精确值**：cos 90° = 0、cos 120° = −1/2、cos 60° = 1/2。否则 `cos(π/2) ≈ 6e-17` 会污染度量张量和对称性判定。
- **分数坐标不强制归一化到 [0, 1)。** 分子晶体的 CIF 常故意把不对称单元的坐标取成 −0.1 之类的值，以保持分子连通。归一化只发生在派生的展开数据里。

## 4. 结构模型

### 4.1 总览

```text
Structure
├── lattice:    Lattice
├── symmetry:   Symmetry
├── sites:      OrderedMap<SiteId, Site>   // 不对称单元，保留导入顺序
└── tolerances: Tolerances
```

`Structure` 是不可变值，每次编辑产生一个新快照（`Arc<Structure>`）。后台任务（对称性检测、将来的 XRD 模拟）在快照上运行；任务返回时如果 revision 已经变了，结果标记为过期。

### 4.2 Lattice

```text
Lattice
├── params:      CellParams { a, b, c, α, β, γ }   // 每项都是 Measured
└── orientation: Standard | Explicit(orthogonal 3×3)
```

- **为什么不直接存 3×3 矩阵**：CIF 给的是晶胞参数，存成矩阵会让 90° 变成 89.99999999999999°；POSCAR 给的是矩阵，只存参数会丢掉朝向。"参数 + 朝向"两头都能保住。
- **标准朝向**：a ∥ x，b 在 xy 平面内，c 构成右手系。`A = R · A_std(params)`；`Standard` 表示 R = I。
- 导入 POSCAR 时从矩阵反算参数和 R；R 在容差内等于 I 就记为 `Standard`。POSCAR 晶格可以是左手系，这时 det R = −1，照常保存，并给出 Info 诊断。
- **硬约束**：
  - 边长 > 0
  - 每个角在 (0°, 180°) 之间
  - 度量张量正定：`1 − cos²α − cos²β − cos²γ + 2·cosα·cosβ·cosγ > 0`

**M10 的实现**（`mw-crystal/src/lattice.rs`）：

- `Lattice { params, orientation }`，`Orientation::Standard | Explicit(Rotation)`。`Rotation` 是按行存的正交矩阵，可以是非正常的（det = −1），和对称操作的旋转部分一样；构造时检查正交（`RRᵀ` 与 I 每个元素相差不超过 10⁻⁹），数值原样保存。
- `CellParams::standard_matrix()` 是 `A_std`，`Lattice::matrix()` 是 `R·A_std`，`to_cartesian` / `to_fractional` 都经过后者。距离、角度、度规张量、体积和倒格子长度与朝向无关。渲染场景（原子、晶胞边、测量线）、测量值、悬停浮层、近邻和成键都经 `Lattice::matrix` / `to_cartesian`，所以显式朝向的结构在视口里按文件给的方向显示。对称性搜索交给 moyo 的是 `A_std`：它只需要度规和分数坐标，标准朝向保证基矢是右手的。
- `Lattice::from_matrix(basis)`：参数由度规张量 `AᵀA` 算出，余弦在 10⁻⁹ 内是 0、±½ 的取精确值，角度在 10⁻⁹ 度内是整数度的取整数（与超胞相同，7.9 节），所以按标准朝向写的立方、六方晶格读回来角度是精确的 90°、120°。`R = A·A_std⁻¹`；参数取了精确值后它不再严格正交，取最近的正交矩阵（奇异值分解的 `U·Vᵀ`）。R 的每个元素与 I 相差不超过 10⁻⁹ 时记为 `Standard`：按标准朝向写的基矢（a 沿 x，b 在 xy 平面内）读回来只差舍入误差。
- 改晶胞参数（`SetCellParams`）保持 R；转为 P1 不换基，朝向不变；晶胞变换（M8，7.8 节）与下面的超胞相同。
- **超胞**（7.9 节）：`A' = A·M`，原子在笛卡尔空间里不动。对角矩阵保持 R；其他矩阵的 R′ 是把新参数的标准朝向转到 `A·M` 上的旋转。因此标准朝向结构的非对角超胞（如钙钛矿的 √2×√2×1）现在带显式朝向，此前放在新参数的标准朝向里，相对原结构转了一个角度；ASE 和 pymatgen 的超胞也保持原坐标系。界面只给对角矩阵，不受影响。
- **导出**：POSCAR 和扩展 XYZ 按 `Lattice::matrix` 写基矢，扩展 XYZ 的笛卡尔坐标也在这个朝向里（9.3、9.4 节）。CIF 只有晶胞参数，隐含右手基：左手系晶格写成 −a, −b, −c（`mw_crystal::right_handed`：参数、位移参数和不确定度不变，坐标 x → −x、原来在 [0, 1) 内的仍在 [0, 1) 内，操作 (W, w) → (W, −w)），否则写出的是镜像，手性结构会变成它的对映体。
- **左手系与对映体**：同一组分数坐标在左手系基矢下是右手系下的镜像。空间群检测（P1 结构的"检测到的对称性"，7.10 节）因此对左手系晶格在 −x 处搜索，P3₁21 和 P3₂21 这样的对映空间群不会认反。由操作集识别空间群类型（5.4 节）也这样处理（M9）：左手系的对称结构由对称化产生，`SymmetryAnalysis` 先用 `right_handed` 换成右手基再识别，CIF 写出本来就先换成右手基。
- **序列化**：`cell` 在六个参数之后加可选的 `orientation`（R 的三行），标准朝向不写，所以已有结构的 JSON 不变；读入时检查正交，不满足时这个结构打不开（[项目文件设计稿](project-format.md) 第 6 节）。

### 4.3 Measured

```text
Measured { value: f64, su: Option<f64> }   // su = 标准不确定度，对应 CIF 的 "3.905(2)"
```

用户手动改过的值，`su` 置空，因为手输的数字没有实验不确定度。导出 CIF 时，只有带 `su` 的值才写括号。

### 4.4 Symmetry

```text
Symmetry
└── operations: Vec<SymOp>          // 完整操作集（含定心平移），是事实来源

SymOp { rot: 3×3 整数矩阵, trans: 3 个有理数（模 1） }
```

- **操作集是事实来源，名称只是标识。** CIF 导入时的优先级：显式 symop > Hall 符号 > H-M 符号 > IT 号。名称与操作集冲突时以操作集为准，并给出警告。
- **空间群类型是派生数据。** 由操作集识别出的 `SpaceGroupType { number, hall_number, hm_symbol, setting }`（见 5.4 节）和其他派生量一样按 revision 缓存，不存进 `Symmetry`；编辑改变操作集后自然重新识别。`Structure.space_group` 只记录来源文件写的名称，用于来源追溯和导出。
- **硬约束**：
  - 包含单位元
  - 在模晶格平移的意义下封闭成群
  - `rot` 是整数矩阵，且 det = ±1
- **平移的解析**：`x+1/3` 直接得到有理数；`0.3333` 这类小数按容差识别为 1/3；识别不出来就报错，不偷偷存成浮点数。
- **P1** 就是只含单位元的操作集。P1 模式不是另一种数据结构。

### 4.5 Site 与 Occupant

```text
Site
├── id:        SiteId                 // 文档内单调递增、永不复用，与标签无关
├── position:  [f64; 3]               // 分数坐标，即不对称单元中的代表点
├── position_su: [Option<f64>; 3]     // 坐标的标准不确定度，只为导出保留；编辑过的坐标没有
├── occupants: Vec<Occupant>          // ≥ 1；混合占位 = 多个 occupant
└── disorder:  Option<{ assembly, group }>

Occupant
├── label:     String                 // 结构内唯一，对应 _atom_site_label
├── species:   Species
├── occupancy: Measured               // 取值 (0, 1]
└── adp:       Option<Uiso | Uaniso>  // v0.x 只保留，不编辑

Species { element, oxidation: Option<i8>, symbol: String /* 原始符号，如 "Fe3+" */ }
```

- **混合占位是同一个 Site 上的多个 Occupant**，比如 Fe/Ni 共占一个位置。拖动时它们一起移动，不会被拖散。CIF 里它们是坐标相同的两行，导入时合并。
- **位置无序（split site）是多个 Site**，用 `disorder` 标记归属，渲染时可以在 A 组 / B 组之间切换显示。
- **空位不建模为一种物种**，由占位率之和 < 1 隐式表示。
- **ADP 挂在 Occupant 上**：物理上 ADP 属于原子而不是位置，CIF 也允许共占的原子有不同的 Uiso。
- **不存任何派生量**：多重度、Wyckoff 字母、位点对称性、`calc_flag` 一律现算。
- **未知元素符号**（如残余峰 `Q1`、`Wat`）映射为占位元素 `X`，并保留原始符号，数据不丢。

### 4.6 Tolerances

| 字段 | 用途 | 默认值 |
|---|---|---|
| `position_tol` | 判定特殊位置、等效原子去重、合并共占 | 0.01 Å |
| `symprec` | 对称性检测 | 0.01 Å |
| `short_contact` | 原子过近警告 | 0.5 Å |

容差存在结构里，同一个项目文件在任何机器上都得到相同的派生结果。

**用 COD 语料校准（2026-10，M2 验收）**：取 COD 里不超过 1 MiB 的全部 504,373 个文件（占全部条目的 94 %），用 `crates/mw-crystal-io/tests/cod_corpus.rs` 里的统计测试（开发指南第 2 节；换容差导入用 `cif::read_with`）。三个初值都经得起数据检验，维持不变。

- **`position_tol` = 0.01 Å**。判据是原子与它自己的对称像之间的距离：小于容差就吸附到特殊位置（落到镜面或二次轴上时位移是这个距离的一半）；两行的位置相差小于容差就合并或去重。文件给出的多重度（或位点对称阶）是判断吸附对错的依据。用九档容差各导入一遍，共 503,216 个结构、3437 万个位点：

  | 容差（Å） | 0.001 | 0.002 | 0.005 | **0.01** | 0.02 | 0.05 | 0.1 |
  |---|---|---|---|---|---|---|---|
  | 吸附的位点 | 15,098 | 25,348 | 29,743 | 30,388 | 30,960 | 31,848 | 32,939 |
  | 漏吸附：满占位位点离自己的像不到 0.5 Å | 13,453 | 5,211 | 1,588 | 1,198 | 982 | 749 | 589 |
  | 漏吸附：文件的多重度小于展开结果 | 7,408 | 6,246 | 5,444 | 5,254 | 5,117 | 4,951 | 4,755 |
  | 误吸附：文件的多重度大于展开结果 | 1,565 | 1,589 | 1,629 | 1,666 | 1,807 | 2,137 | 2,714 |
  | 不同无序组的位点落在同一位置 | 21,415 | 21,469 | 21,603 | 21,799 | 22,272 | 24,534 | 32,304 |
  | 合并成混合占位的行 | 82,483 | 82,676 | 82,914 | 83,093 | 83,374 | 83,949 | 85,080 |

  从 0.005 Å 到 0.01 Å，漏吸附少了 580 个，误吸附只多 37 个。再往上，漏吸附减少得越来越慢：多重度不符的约 4,700 个在任何容差下都在，是文件本身的问题（多重度写错、操作集不全）。误吸附和落在同一位置的无序位点却开始加速增加。误吸附会改动数据，漏吸附只留下一条警告、数据不变，所以在 0.01–0.05 Å 这段平台里取最保守的 0.01 Å，与 `symprec` 相同。在 0.01 Å 下，吸附的位移 79 % 小于 0.001 Å，20 % 在 0.001–0.003 Å，几乎都是坐标只写到 4–5 位小数造成的（如用 0.3333 表示 1/3）。
- **`symprec` = 0.01 Å**。每隔 20 个文件取一个结构（不超过 500 个原子，共 21,677 个），展开成 P1，把坐标四舍五入到 4 位或 6 位小数，模拟别的程序写出的 P1 文件，再看对称性搜索能否找回原来的操作集：

  | `symprec`（Å） | 0.001 | 0.003 | **0.01** | 0.03 | 0.1 |
  |---|---|---|---|---|---|
  | 4 位小数：找到的操作少于原来 | 12,911 | 693 | 6 | 2 | 1 |
  | 4 位小数：找到的操作多于原来 | 44 | 45 | 50 | 61 | 93 |

  坐标写到 6 位小数时各档都能找回（少于原来的不超过 12 个）。0.01 Å 是 4 位小数的坐标也能找回对称性的最小值，再大只会多找到赝对称。另有约 1.2 % 的结构搜索没有结果：它们有两个原子落在同一位置（不同无序组的位点，或 Si/Al 分两行写成的满占位位点），moyo 不接受重叠的原子（11 节）。
- **`short_contact` = 0.5 Å**。满占位、有序的位点之间 1 Å 以内的距离：

  | 距离（Å） | < 0.5 | 0.5–0.6 | 0.6–0.7 | 0.7–0.8 | 0.8–1.0 |
  |---|---|---|---|---|---|
  | 含氢 | 1,058 | 1,145 | 5,537 | 40,331 | 1260 万 |
  | 不含氢 | 1,059 | 382 | 509 | 594 | 2,222 |

  X 射线定出的 X–H 键长从 0.6 Å 起陡增，0.5 Å 以下几乎只有重叠的原子、残留峰之类的错误。不含氢的原子在 1 Å 以内都不该出现，但一个阈值要兼顾两类，取 0.5 Å：全语料有 902 个文件（0.18 %）报原子过近，正常的 X–H 键不会被报。按是否含氢区分阈值（不含氢取 1.0 Å）能再多发现约 3,700 处，留到成键规则可以按元素对设置时一起做。

## 5. 派生数据

全部按 `Structure.revision` 缓存，不持久化。

### 5.1 等效原子展开与 AtomRef

对每个 Site 计算它的轨道（orbit）：

1. 按存储顺序把每个操作作用在代表点上。
2. 把结果归一化到 [0, 1)。
3. 用最小像距离在 `position_tol` 内去重。

第 k 个不重复的位置就是成员 k，同时记下生成它的操作 `g_k = (W_k, w_k)`。

```text
AtomRef { site: SiteId, member: u16, cell: [i32; 3] }   // 晶体中某个具体的原子
```

只要操作集的顺序和该位点的位点对称性不变，成员编号就是稳定的。选区、测量、键都引用 `AtomRef`。

### 5.2 位点对称性与约束子空间

- **位点对称群** G_s：所有满足 `g(x) ≡ x (mod 晶格)` 的操作。多重度 = |操作集| / |G_s|（相对当前晶胞）。
- **投影算子** `P_s = (1/|G_s|) · Σ W_i`，即对 G_s 的线性部分求平均。它与基底无关，在笛卡尔基下就是正交投影，所以拖拽位移投影后正好是"最接近用户手势的合法位移"。
- **自由度** = rank(P_s)：一般位置为 3，镜面上为 2，旋转轴上为 1，反演中心上为 0。
- **自由坐标的参数化**：把 range(P_s) 的基化成行最简形，主元坐标作为自由参数，其余坐标写成主元的线性组合加常数。得到的就是 Wyckoff 表达式，例如 `x, 2x, 1/4`。这一步不依赖 Wyckoff 表，对任何 setting 都成立；能识别出标准 setting 时，再额外显示 Wyckoff 字母。

### 5.3 其他派生量

- **化学式与 Z**：Σ（轨道大小 × 占位率）。
- **密度**：需要原子量表。
- **近邻表**：cell list，复杂度 O(N)。
- **键**：由近邻表和成键规则（文档层的分析设置）得出，记为 `(AtomRef, AtomRef)`，包含跨周期边界的晶胞偏移。M3 的实现（`mw-crystal/src/bonds.rs`）：
  - **规则**：两原子距离不超过共价半径之和（Cordero 2008，到 Cm 为止；没有半径的元素不成键）加容差 0.45 Å，且不小于 0.4 Å。容差和下限沿用 Jmol / Open Babel 的默认值。
  - **金属之间默认不成键**：离子晶体里阳离子之间常比共价半径之和还近（金红石的 Ti–Ti 为 2.96 Å，而 Ti 的共价半径之和为 3.20 Å），画出来会遮住配位多面体。非金属和类金属（B、Si、Ge、As、Sb、Te 等）不受此限。
  - **无序**：同一无序组合（assembly）里不同组的位点是互相替代的位置，彼此不成键；组 0 视为有序部分。
  - **混合占位**：按第一个占位者的元素判断，和绘制一致。
  - **周期性**：只搜索单胞内原子与其周围镜像的距离，每根键存一次，第一个原子在原点晶胞。搜索范围按晶面间距算出，斜晶胞也不会漏。
  - **按元素对设定截断距离、用户覆盖**还没有做；`BondRules` 目前只有上面的默认值。
- **显示键**：显示范围里两个端点都被显示的键。显示原子的 `AtomRef` 带着各自的晶胞偏移（面、棱、角上补出的像是相邻晶胞的同一个轨道成员），所以从每个显示原子出发，把键平移到它的晶胞，另一端也在显示范围里就画出来。
- **边界原子**（坐标为 0 的原子同时画在 1 处）属于视图层的"显示范围"，不在这一层处理。

### 5.4 空间群类型、Wyckoff 位置与晶胞约束（M2）

符号表、Wyckoff 表和对称性搜索来自 moyo（见第 11 节），对它的调用全部集中在 `mw-crystal/src/tables.rs`，其余计算在本仓库里用精确有理数完成。

- **识别操作集的空间群类型**：先与 530 个表列设定（Hall 号 1–530）的完整操作集逐一精确比较，命中即得到类型和设定，坐标不需要变换。命中不了（非表列的原点或晶胞，例如 F 胞描述的 I4/mmm、R 的反式设定）时，在一个被操作集精确保持的度量（实际度量对点群取平均）下，放三个一般位置的探针原子按操作集展开，交给 moyo 搜索，得到类型和到标准设定的变换 (P, p)，并核对找到的操作数与操作集相同。
- **位点对称性**：在 `position_tol` 内找出 G_s，每个成员带上把像拉回到 x 旁边的晶格平移；平均得到 `P_s` 和平均平移 `t̄`，两者都是精确有理数。特殊位置就是 `t̄ + range(P_s)`，5.2 节的参数化里的常数由 `t̄` 精确算出，并取模 1。找到的集合在容差内不成群时（容差接近特殊位置间距时才可能），容差逐级缩小。只依赖一个主元的坐标记为"跟随"，依赖多个主元的（只在非标准设定里出现）记为"组合"。跟随坐标可以直接输入，由它反解出主元；组合坐标不能单独编辑（7.5 节，M7）。
- **Wyckoff 位置**：表列多重度 = 表列设定的操作数 / |G_s|。该多重度的位置只有一个时直接取它；否则把位点（必要时先按 (P, p) 变换）在该设定下的各个像逐一与表列坐标三元组比较，落在某个三元组上（`position_tol` 内）的即是。表列设定命中时字母按该设定给出，否则按标准设定给出，界面会注明。
- **晶胞约束**：满足 `Wᵀ·G·W = G` 的度量构成一个线性空间（精确求零空间）。边长平方在这个空间上恒等则联动；夹角余弦恒为 0（90°）或在等长边之间恒为 ∓½（120°、60°）则固定；两个夹角余弦恒等则联动（菱方轴）。
- **原子的对称性**（7.10 节的检测）：P1 结构打开时，把展开后的原子按占位情况分成不同物种（M9 起还区分氧化态和无序组，与对称化相同），用 `symprec` 交给 moyo 搜索，结果显示在属性面板里；原子超过 2000 个时不自动搜索。对称化（`Symmetrize`，M9）见 7.10 节。

## 6. 文档层

```text
CrystalDocument
├── structure:   Arc<Structure>, revision
├── meta:        标题、备注
├── provenance:  source        — 格式、文件名、哈希、原始文本、未识别字段
│                derived_from  — 来源文档 + 生成它的命令（如超胞）
│                history       — 已提交命令的序列
├── analysis:    BondRules     — 元素对截断距离、共价半径 × 系数、用户覆盖
└── annotations: Vec<Measurement>   // 距离、键角、二面角，引用 AtomRef
```

**M4 的实现**（`mw-crystal/src/document.rs`）：`CrystalDocument` 持有结构（`Arc<Structure>`）、始终与之一致的派生数据、测量（`Annotation`，带"已失效"标记）、revision 和撤销历史。元数据、来源记录和成键规则的设置随 M5、M6 加入；会话里的文档名、所属项目和导入诊断仍由界面的 `StructureDocument` 持有。

文档在项目文件里怎么存（结构、测量、来源记录、编辑记录、视图状态），见[项目文件设计稿](project-format.md)。

**CIF 往返策略。** 导入时把字段分成三类：

| 类别 | 例子 | 结构被修改后 |
|---|---|---|
| 描述性 | 出版信息、作者、实验条件 | 原样导出 |
| 由结构派生 | `_cell_volume`、`_chemical_formula_sum`、`_exptl_crystal_density_diffrn`、`_atom_site_Wyckoff_symbol`、`_geom_*` | 丢弃，由模型重新生成 |
| 未识别 | 其余字段 | 结构未修改时原样导出；修改后丢弃，并在导出报告中列出 |

M5 的实现（`mw-crystal-io/src/kept.rs`）：

- 导入时按标签把每个字段归入四类之一：模型读取的（晶胞、对称操作、空间群名称、位点、ADP、无序）、派生的（上表，外加 `_symmetry_cell_setting`、`_atom_site_cartn_*`、`_exptl_crystal_F_000` 等）、描述性的（`_audit_`、`_publ_`、`_journal_`、`_citation_`、`_database_`、`_cod_`、`_chemical_name_`、`_cell_measurement_`、`_exptl_`、`_diffrn_`、`_reflns_`、`_refine_`、`_computing_`、`_pd_` 开头）和未识别的。后两类按文件顺序保存在 `ImportedBlock.fields`（`CifFields`）里，标签保留文件里的大小写，值保留"是否带引号"（只在 `?`、`.` 这类需要时）。
- 一个 loop 只要有一列是模型读取或派生的，就整个由模型重新生成，其余列不保留；只有原子位点的两个 loop 例外：`_atom_site_` 和 `_atom_site_aniso_` 里模型不读的列（如 `_atom_site_calc_flag`、`_atom_site_attached_hydrogens`）按原子标签保存，导出时写回对应的行。导入时跳过的行（哑原子、重复列出的行）的值不保留。
- "结构是否修改过"由调用方给出；`ImportedBlock::write_options` 把当前结构与导入时的结构比较。修改过时，未识别的字段和列不写，标签列在 `Written.dropped` 里，界面用通知告诉用户。
- 文档层（第 6 节的 `provenance`）还没有实现，`StructureDocument` 暂时直接持有导入的数据块；M6 的来源记录接手。

## 7. 编辑语义

### 7.1 两种编辑模式

| | 对称模式 | P1 模式 |
|---|---|---|
| 编辑对象 | Site：一次编辑作用于全部等效原子 | 单个原子（每个原子都是独立的 Site） |
| 进入方式 | 打开带对称性的结构（空间群 ≠ P1 时默认） | `ExpandToP1` 命令，或打开没有对称信息的文件 |
| 离开方式 | `ExpandToP1`（可撤销） | `DetectSymmetry` → 预览 → `Symmetrize`（可撤销） |

**规则：对称模式下，任何会破坏对称性的编辑都直接拒绝，不会自动降为 P1。** 提示示例："删除单个等效原子会破坏 Pm-3m 对称性。[转为 P1 后继续] [取消]"。转为 P1 必须是用户看得见的显式动作。

### 7.2 命令目录

| 命令 | 对称模式下的语义 | 主要校验 |
|---|---|---|
| `SetCellParams` | 受约束的参数联动（见 7.3），分数坐标不变 | 度量张量正定 |
| `MoveSite` | 拖拽，位移投影到约束子空间（见 7.4） | 原子过近警告 |
| `SetCoordinate` | 数值输入一个坐标，联动坐标跟随（见 7.5） | 固定坐标只读 |
| `AddSite` | 加入不对称单元，靠近特殊位置时吸附 | 与已有轨道重合则拒绝 |
| `RemoveSite` | 删除整个轨道，确认文案写明原子数 | — |
| `SetSpecies` | 整个轨道一起替换元素 | — |
| `SetOccupancy` / `AddOccupant` / `RemoveOccupant` | 编辑混合占位 | 占位率之和 > 1 时警告 |
| `RenameLabel` | — | 标签唯一 |
| `SetDisorder` | — | — |
| `TransformCell(P, p)` | 换基 / 换原点：转原胞、转标准惯用胞、Niggli 约化、换 setting | P 为有理矩阵，det P > 0 且在 1/8 到 8 之间；新基矢是结构的晶格平移；每个操作把新晶格映射到自身 |
| `ExpandToP1` | 展开为 P1 | — |
| `Symmetrize { symprec, standardize }` | 按检测结果对称化（7.10 节） | 预览里显示最大位移 |
| `MakeSupercell(M)` | **生成新文档**，结果为 P1 | M 为整数矩阵，det > 0 |

**M4 的实现**（`mw-crystal/src/edit.rs`）：

- `Edit` 是可序列化的枚举（serde，`{"command": "remove_site", "site": 2}` 这样的带标签 JSON），已实现 `SetCell`、`SetSpecies`、`SetOccupancy`、`AddOccupant`、`RemoveOccupant`、`RenameLabel`、`RemoveSite`，以及 P1 下的 `SetPosition`，和把几条编辑当作一步的 `Batch`。Occupant 用标签指明（结构内唯一）。M5b 加了 `ExpandToP1`（逆命令是恢复整个结构的 `RestoreStructure`，7.12 节）；P1 结构上执行时拒绝（`AlreadyP1`）。`expand_and_remove` 生成"转为 P1 后删除这些原子"的 `Batch`，撤销一次回到对称结构。
- `Edit::apply` 在结构的副本上执行，返回新结构、逆命令、ID 映射（7.11 节）和警告；出错时什么都不改，`Batch` 里后面的命令出错也一样。
- 逆命令要原样恢复被改掉的东西（s.u.、ADP、位置顺序），所以另有只作逆命令用的 `RestoreCell`、`RestoreOccupant`、`RestoreSite`：它们不做约束联动，按原样放回。逆命令的逆命令就是重做。
- 命令只指向整个位点。请求指向单个原子时（视口里点选的原子、AI 调用），先由 `target_sites` 换算：位点的轨道只有一个原子（P1 下总是如此），或请求覆盖了全部等效原子时，等同于整个位点；否则在对称模式下拒绝（`EditError::BreaksSymmetry`），引导（`Guidance`）为"改全部 N 个"或"转为 P1"，界面和 AI 按它给出 7.1 节的选项。
- 拒绝是带数据的错误 `EditError`：稳定的 `code()`、英文的 `Display`（给 AI 和日志），以及可选的引导；界面按变体自己翻译。
- M7 加入对称模式下的几何编辑：`MoveSite`、`SetCoordinate`、`AddSite` 和只作逆命令用的 `RestorePosition`，见 7.4–7.6 节。`SetPosition` 不再只限 P1：位点取新位置的位点对称性，原来"对称模式下拒绝"的错误 `MoveUnderSymmetry` 已删除。
- 命令除了警告还返回 `EditInfo`（第 8 节的 Info 级）：吸附到特殊位置（`Snapped`，位移 ≥ 10⁻⁴ Å 时）和多重度变化（`Multiplicity`）。它和警告一起出现在 `Applied` 和 `CrystalDocument` 的 `Outcome` 里。
- M8 加入 `TransformCell` 和只作逆命令用的 `RestoreBasis`，拒绝的原因是 `EditError::Transform`，见 7.8 节。
- M9 加入 `Symmetrize` 和只作逆命令用的 `RestoreAtoms`，拒绝的原因是 `EditError::Symmetrize`，见 7.10 节。

### 7.3 修改晶胞参数

- **默认保持分数坐标不变**，原子随晶胞缩放，与 VESTA 一致。v0.x 不提供"保持笛卡尔坐标"的选项。
- **约束模式由对称性推出。** 点群必须保持度量张量不变，即对所有 W 都有 `Wᵀ·G·W = G`。由此可以算出：
  - 哪些边长必须相等
  - 哪些角固定为 90° 或 120°
  - 菱方 setting 下 α = β = γ

  每个操作集只需算一次。
- UI 中联动的字段显示链接图标，固定的字段只读。例如立方晶系只有 a 可编辑，b、c 跟随。
- 导入时如果晶胞参数与对称性不一致（比如立方晶系 a = 3.9050、b = 3.9051），给出诊断，并提示用"对齐"修正（见下）。

**v0.2 验收时的补充**（`mw-crystal/src/edit.rs` 的 `constrained_cell`）：

- **改晶胞参数的结果总与对称性一致**：给出的值照上面联动；没给的联动参数取它跟随的参数的原值（连同不确定度），固定的角取对称性要求的值（90°、120° 或 60°，取自按点群平均的度规张量，`from_metric` 取精确值）。所以导入时略有出入的晶胞，改任何一个参数都会顺带对齐；给固定的角输入它应有的值不算改动。对称性一致的晶胞行为不变。
- **对齐**：`SetCellParams` 不给值时只做上面的对齐，结果与原晶胞相同就不产生一步。偏差超过导入警告的阈值（`CELL_DEVIATION`，边长 10⁻³ Å 或夹角 10⁻³°，与导入诊断相同，取自 `mw-crystal`）时，属性面板在晶胞参数下说明偏差，并给出"对齐"按钮（动作 `AlignCell`），一步撤销；导入诊断的文字指向这个按钮。能力 `structure.set_cell` 的说明写明结果总与对称性一致，AI 给 a 原值就能对齐。
- 原先这里写的是"提示对称化"，但对称化（7.10 节）只对检测到更高对称性的结构开放，已经有这些对称性的结构会被拒绝，所以改为在晶胞参数上就地对齐。

### 7.4 拖拽移动位点

用户拖动的是某个具体原子 `AtomRef(s, k, n)`，它的位置是 `W_k·x_s + w_k + n`：

1. 手势给出笛卡尔位移 Δr，换算成分数位移 `Δx = A⁻¹·Δr`。
2. 换算到代表点上：`Δx_s = W_k⁻¹·Δx`。
3. 投影到约束子空间：`Δx_s' = P_s·Δx_s`，原子因此留在特殊位置上。
4. 更新代表点，所有等效原子随之移动。

补充规则：

- **一次拖拽 = 一步撤销**：拖拽过程只是会话层的预览，松手时提交一条 `MoveSite`。
- **脱离特殊位置**：按住修饰键（如 Alt）时跳过投影。位点对称性降低、多重度增大，状态栏要明确显示，例如"Fe1 多重度 1 → 6"。
- **落到特殊位置**：一般位置的原子被拖到特殊位置附近（`position_tol` 以内）时自动吸附，多重度减小，同样给出反馈。
- **原子过近**：移动后任意两个原子（包括自身的等效原子）距离小于 `short_contact` 时给出警告，但不拒绝，因为用户可能还在编辑中途。

**M7 的实现**（`mw-crystal/src/placement.rs`，命令在 `edit.rs`）：

- 命令是 `MoveSite { atom, displacement, leave_special_position }`。位移用分数坐标，是被拖原子的位移，所以 `W_k⁻¹` 的换算在领域层：`W_k` 是生成成员 k 的那个操作（`expand::members` 记下的第一个），`W_k⁻¹` 是整数矩阵（行列式 ±1，伴随矩阵乘行列式）。`atom` 的晶胞偏移不影响结果，成员号超出轨道时拒绝（`UnknownAtom`）。笛卡尔位移到分数位移的换算（第 1 步）在界面里做，经 `Lattice::to_cartesian` 的三个基矢，与晶格朝向无关。
- **投影与吸附**：不脱离时，新位置是 `x + P_s·W_k⁻¹·Δx`，它仍在原来的特殊位置上；再看新位置在 `position_tol` 内的位点对称群，比原来的大（落到更高对称的特殊位置附近）才吸附过去，即取 5.4 节的平均位置。脱离时不投影，新位置只要有任何非平凡的位点对称群就吸附，所以移开不到容差的距离会吸回原处，等于沿特殊位置移动。吸附的位移达到 10⁻⁴ Å 时报 `EditInfo::Snapped`，阈值与导入相同（9.1 节）。
- **多重度变化**：比较移动前后轨道的大小，不同就报 `EditInfo::Multiplicity { before, after }`，界面显示为"O1 多重度 4 → 16"。
- **原子过近**：其他位点的原子报 `ShortContact`，自身的等效原子之间报 `CloseImages`（例如刚离开镜面一点点时），都只警告。
- **不确定度**：值变了的坐标去掉 s.u.（4.5 节），没变的保留；逆命令 `RestorePosition` 原样放回位置和 s.u.，不投影、不吸附。P1 下的 `SetPosition` 也按这条规则。
- **界面**（`mw-structure/src/moving.rs`，`docs/design/ui-shell.md` 4.2 节）：移动模式下按在原子上拖动。拖动中每次指针移动都在结构副本上执行同一条 `MoveSite`，只展开原子和找键、不做对称性分析，画成预览；视口保持相机绕的中心，预览不会让画面平移。松手时执行一次，成为一步撤销。⌥（Alt）随时切换是否脱离，不移动指针也会更新预览；Esc 放回原处。

### 7.5 数值输入坐标

属性面板按 5.2 的参数化方式显示坐标：

- **主元坐标**：可编辑。修改后按线性关系更新联动坐标，例如在 `x, 2x, z` 中改 x，y 跟着变。
- **只依赖一个主元的从属坐标**：可编辑。先反解出主元再联动，例如改 y，则 x = y/2。
- **常数坐标**（如 `1/4`）：只读，显示锁图标。
- 能识别 Wyckoff 字母时，显示在坐标旁边，例如 `6h · x, 2x, 1/4`。

> 实现提示：不要用 `P_s` 的对角元来判断某个坐标能不能改。六方等晶系的分数坐标基不正交，`P_s` 的对角元可能为 0，而对应的坐标其实并不固定（`x, 2x, z` 就是这种情况）。应使用行最简形参数化。

**M7 的实现**（`SetCoordinate { site, axis, value }`，`CoordinateForm::with_coordinate`）：

- 由当前位置的位点对称群得到 5.2 节的参数化，主元坐标就是自由参数。改主元：它取输入值；改跟随坐标：由 `value = c·x_p + 常数 + n` 反解出主元 x_p，其中整数 n 是这个坐标当前相对参数化的晶格平移。
- 只重算依赖被改主元的坐标，每个保留自己原来的晶格平移，所以 `x, −x, 1/2` 在 (0.2, 0.8, 0.5) 上改 x 为 0.25，y 得 0.75 而不是 −0.25（第 3 节：坐标不归一化）。不依赖它的坐标原样不动，输入的那个坐标也原样保存（不经投影的浮点运算，输入 0.3125 就存 0.3125）。
- 常数坐标被拒绝（`FixedCoordinate`），组合坐标也被拒绝（`CombinedCoordinate`，引导是改它依赖的主元）；输入与原值相差不到 10⁻⁹ 时什么都不改，不报错，与晶胞参数一致。
- 新位置落到更高对称的特殊位置附近时吸附，规则与 7.4 节相同；例如金红石 4f 的 x 输入 0.0001，O1 吸附到 2a，多重度 4 → 2。
- P1 下三个坐标都是主元，`SetCoordinate` 就是改那一个坐标；界面的坐标字段在两种模式下都走这条命令。跟随坐标的字段显示链接图标和表达式（如 `= x`）且可以输入，常数坐标显示锁并禁用，组合坐标显示表达式并禁用。

### 7.6 增删位点

- **AddSite**：在约束平面上点击，或直接输入坐标。
  - 先在 `position_tol` 内找出位点对称群，再取 `x_sym = (1/|G_s|) · Σ g_i(x)` 作为吸附位置；求和前各项先平移到离 x 最近的晶格像。
  - 与已有轨道重合时拒绝，并提示："与 Fe1 重合，是否改为在 Fe1 上添加混合占位？"
  - 标签自动生成：元素符号 + 最小的未使用编号。
- **RemoveSite**：反馈写明删除范围，例如"已删除 O1（3 个原子）"。删除可以撤销，所以界面不再弹确认（M4）。对称模式下不能只删其中一个。

**M7 的实现**（`AddSite { position, species, occupancy, label }`）：

- 吸附用 5.4 节的平均位置（`special_position`），保留离输入位置最近的晶格平移，不归一化到 [0, 1)；位移达到 10⁻⁴ Å 时报 `EditInfo::Snapped`。
- 新位点排在不对称单元的最后，ID 取现有最大值加一（与转为 P1 一致）。逆命令是 `RemoveSite`，它的逆命令 `RestoreSite` 放回同一个 ID，所以重做精确。
- 吸附后的位置与任何已有位点的原子（含等效原子）相距不到 `position_tol` 时拒绝（`CoincidentSite`），引导是 `Guidance::AddOccupant`：改为在那个位点上添加混合占位。距离在 `position_tol` 和 `short_contact` 之间时照常添加，给出原子过近的警告。
- 不给标签时按 7.7 节的规则生成；给出的标签要合法且唯一。元素、占位率的检查与 `AddOccupant` 相同。
- 界面：位点标签页的"添加位点…"和命令面板打开对话框，输入元素、占位率和分数坐标；对话框随输入说明将吸附到哪个特殊位置、相距多远、晶胞内有几个等效原子。重合时关掉这个对话框，再弹一个，提出把元素作为混合占位加到那个位点上。还没有在约束平面上点击添加。

### 7.7 元素替换与占位

- **`SetSpecies`** 作用于 Occupant，整个轨道一起替换。标签保持不变（例如 `Ti1` 换成 Zr 后仍叫 `Ti1`），需要时用 `RenameLabel` 改名；改元素不连带改名，与"不静默修改数据"一致。
- **部分替换**（如 Fe → Fe₀.₉Ni₀.₁）：在同一个 Site 上 `AddOccupant`，再调整占位率。结构保持对称，表示的是无序的平均结构。没有给标签时，新 Occupant 的标签按 7.6 节的规则生成（`Ni1`、`Ni2`……）；位点的最后一个 Occupant 不能删除，引导是删除整个位点。
- **有序替换**（只换其中某几个原子）：只能在 P1 下做，通常先建超胞。
- **占位率校验**：
  - 每一项必须在 (0, 1] 之间。
  - 同一 Site 的占位率之和超过 1 + tol 时只警告、不报错，因为精修结果常常略超 1。
  - 同一 disorder assembly 内相邻 split site 的占位率之和做同样的检查（v0.2 验收时补上，`split_occupancy_warning`）。互为替代的位点与成键的规则相同：无序组合相同、无序组不同，且都不是 0 组（SHELX 的有序部分）；相邻指两个原子相距不到两种元素的共价半径之和（同时存在会比共价键还近），没有共价半径的元素用 `short_contact`。被改的位点加上每个其他无序组里相邻位点的最大占位率，超过 1 + tol 时警告 `SplitOccupancySum`，写明是哪几个位点；位点自己就超过 1 时只报那一条。改占位率和添加占位者时检查。SHELX 的负 PART（与自己的对称像互为替代）还不处理。

### 7.8 晶胞变换

采用《国际晶体学表》A 卷的 (P, p) 约定：新基 `A' = A·P`，新原点在旧基下的坐标为 p。

- 坐标：`x' = P⁻¹·(x − p)`
- 操作：`W' = P⁻¹·W·P`，`w' = P⁻¹·(w + W·p − p)`
- **晶胞变大**（det P > 1，如原胞 → 惯用胞）：旧晶格中不属于新晶格的平移，作为定心平移补进操作集。
- **晶胞变小**（如惯用胞 → 原胞）：只相差一个新晶格平移的操作合并成一个。

变换后的不对称单元仍然是不对称单元，不需要重新展开。P、p 存为有理数，因此可以精确撤销。

**M5b 的实现**（`mw-crystal/src/transform.rs`）：转为 P1 和超胞都是换一个晶胞来描述同样的原子，所以放在一起。位移参数和坐标的不确定度随原子一起变换：分数位移经线性映射 T（对称操作的旋转部分，或换基的 M⁻¹）变为 `B' = T·B·Tᵀ`，`B = N·U·N`，`N = diag(a*, b*, c*)`，再换回新晶胞的 U。系数在舍入误差内是整数时取整数，所以只在等长轴之间换位置的分量（四重轴下的 U11 = U22）保持原值、逐位相同；不确定度按平方和传递（不知道相关性），有一项没有不确定度结果就没有。坐标的不确定度同理。

**M8 的实现**（`mw-crystal/src/cell_transform.rs` 是 (P, p) 与预设，`transform.rs` 是换基本身，命令在 `edit.rs`）：

- **命令**：`TransformCell { transform }`。`CellTransform` 存有理数的 P 和 p，`matrix[i][j]` 是 P 第 i 行第 j 列，第 j 列是新基矢 j 在旧基下的坐标（与超胞相同）；序列化成分数文本，如 `{"matrix": [["0", "1/2", "1/2"], …], "origin": ["0", "0", "0"]}`。构造时要求 det P > 0（为 0 构不成晶胞，为负会把基矢变成左手系），且在 1/8 到 8 之间：晶胞最多放大或缩小 8 倍，更大的是超胞（7.9 节）。矩阵运算用带溢出检查的 128 位精确分数，数大到算不了时拒绝（`TooLarge`），不会算错。
- **操作**：`W' = P⁻¹·W·P`、`w' = P⁻¹·(w + W·p − p)`，都精确。两种情况拒绝：新基矢不是结构的晶格平移，即它的平移不在操作集里（`NotATranslation`，新晶胞比格子允许的小，如 P1 结构把 a 减半）；某个操作不能把新晶格映射到自身，即 W' 不是整数矩阵（`BreaksSymmetry`，如四方结构的 2a × a × c）。通过后，旧晶格的平移在新基下模 1 的集合（由 P⁻¹ 的三列生成）作为定心平移补进操作集；只差一个新晶格平移的操作模 1 后相同，去重即合并。新操作集正好是某个表列设定时按表里的顺序给出：同一转动、只差定心平移的几个操作哪个在前取决于从哪个晶胞变过来，按表的顺序，变过去再变回来操作的顺序也不变。
- **位点**：同样的位点、ID、标签和占位者，代表点 `x' = P⁻¹·(x − p)`，不归一化（第 3 节）。位移参数和坐标的不确定度经 P⁻¹ 变换，用的是 M5b 的同一套函数。
- **数值**：变换后的坐标、晶胞参数和各向异性位移参数在舍入误差内（8×10⁻¹⁵，大于 1 的数按大小放大）是分母不超过 24 的分数或不超过 10 位的小数时，取这个数。从文件读来的数值变过去再变回来因此逐位相同；附近没有这样的数的（例如拖动后的坐标）保持计算结果，与原值只差舍入误差。
- **晶胞参数**：一个新基矢只是某个旧基矢的倍数时，长度按倍数缩放，不确定度一起缩放；两个这样的基矢之间的角度是原来的角或 180° 减去它，不确定度保留。其余由度规张量 `Pᵀ·G·P` 算出（与超胞相同，直角和 60°、120° 取精确值），不带不确定度，因为按平方和传递需要不知道的相关性。所以换轴、换原点不丢晶胞的不确定度；转原胞时变成斜向的基矢丢掉它们，坐标和位移参数的不确定度按平方和传递，变回来不会逐位还原。
- **朝向**（4.2 节）：新基是 `A·P`。P 是对角元都为正的对角矩阵时保持 R；否则取把新参数的标准朝向转到 `A·P` 上的旋转，与超胞相同。对角元带负号的 P（如 −a、−b、c）把轴翻过来，也要转朝向；M8 原先对它也保持 R，原子因此在笛卡尔空间里转了 180°，M9 的标准化用到这种 P 时发现并修正。原子相对新原点在笛卡尔空间里不动（原点移动 p 时，模型里的笛卡尔坐标整体平移 −A·p）；det P > 0，所以左手系仍是左手系。标准朝向的惯用胞转原胞后是显式朝向，转回来又是标准朝向。
- **空间群名称**：类型不变，`Structure.space_group` 记的是来源文件写的名称，不改。
- **撤销**（7.12 节）：逆命令 `RestoreBasis { transform, structure }` 放回整个结构，因为浮点坐标经 P⁻¹ 再经 P 会差舍入误差；`transform` 是 `(P⁻¹, −P⁻¹·p)`，用来让引用跟着原子走（7.11 节）。它的逆命令还是 `RestoreBasis`，撤销和重做都逐位精确。单位变换什么都不改，不产生一步。

**预设**（`CellPreset::transform`，对 moyo 的调用都在 `tables.rs`）：给出这个结构的 (P, p)；已经是那个晶胞时给单位变换。

- **原胞**：操作集里没有纯平移时就是当前晶胞。正好是表列设定时用 moyo 的定心矩阵（`Centering::inverse`），也就是《国际表》的选法，如 F 的 a′ = ½(b + c)、b′ = ½(a + c)、c′ = ½(a + b)，原点不动；不是表列设定时用 moyo 标准化给出的原胞。
- **标准惯用胞**：正好是标准设定时不变，否则用 moyo 标准化（`std_linear`、`std_origin_shift`）给出的。三斜的 P1 只有一个设定，它的约化胞是下面的 Niggli 预设。
- **Niggli 约化**：先转原胞，再对原胞的基矢（取标准朝向，保证右手系）做 moyo 的 Niggli 约化，`P = P原胞·T`。已经约化时不变。
- **换设定**：同一类型的其他表列设定（单斜的唯一轴和晶胞选择、正交的轴序、原点选择 1 和 2、六方轴和菱方轴），`other_settings` 列出它们。moyo 一次只标准化到一个设定，而且换不了单斜的唯一轴（它的修正矩阵只覆盖晶胞选择），所以变换是"当前 → 标准设定"接上"目标设定 → 标准设定"的逆，两段都由 moyo 给出。
- **规范化**：moyo 给的 (P, p) 只确定到等价的选择。例如 Fm-3m 已在标准设定时，moyo 的 `std_linear` 是一个转动；与结构的任一操作复合，或与比操作集更多的晶格对称（如极轴的两个方向）复合，新操作集可以完全相同。所以先在 `W·P` 中选新基离标准朝向最近的（W 取操作的转动部分和晶格的整数对称矩阵，元素为 −1、0、1；离标准朝向的远近按把标准朝向转到新基上的转角），惯用胞和设定还允许两两反转新轴，并且非锐角多的优先（单斜 β ≥ 90°、六方 γ = 120°）；再在分母为 8 和 6 的原点平移中，选能保持新操作集的最短平移（原来的原点可用时就是它），一样长时选让位点坐标（折回 [0, 1)）之和最小的；沿极轴原点任意，取 0。最后核对结果正好是目标的操作集。
- **测试**（`cell_transform.rs`）：81 个有定心的标准设定（带一般位置的原子和各向异性位移参数）转原胞再转惯用胞逐位相同；300 个非标准设定都从标准设定变得过去，再变回标准惯用胞逐位相同；Křivý 与 Gruber（1976）的例子 A = 9、B = 27、C = 4、ξ = −5、η = −4、ζ = −22 约化为 4、9、9、9、3、4，以及 fcc、bcc 的 Niggli 胞；刚玉从六方轴到菱方轴（α = 55.28°，10 个原子）；硅的原点选择 2 → 1；P2₁/c 换到唯一轴 c 时 γ = 100°；显式朝向和左手系的结构转原胞、Niggli 再转回来，原子在笛卡尔空间不动、手性不变；位移参数和不确定度的规则（换轴逐位保留，转原胞后笛卡尔下的位移椭球不变）；引用和测量跟着原子走，撤销重做精确；拒绝的每种情况。
- **界面**：属性面板对称性区域的"晶胞变换…"和命令面板打开对话框（[界面设计稿](ui-shell.md) 第 5 节），选预设或输入 P、p，随输入预览新晶胞参数、晶胞内原子数和空间群设定，确认后执行一步。

### 7.9 超胞

- `MakeSupercell(M)`：新晶格 `A' = A·M`。P1 展开后的每个原子在新晶胞中有 |det M| 个像，取 `x' = M⁻¹·(x + n)` 中落在 [0, 1)³ 内的那些。
- **结果是一个新文档**，`derived_from` 指向原文档。这样原来的对称结构保持完整；超胞通常是下游计算（DFT）的输入，本来就是另一个对象。
- 结果为 P1，可以再跑 `DetectSymmetry`。部分占位原样保留，不自动有序化。

**M5b 的实现**（`mw_crystal::make_supercell`）：

- M 是任意行列式为正的整数矩阵（`matrix[i][j]` 是第 i 行第 j 列，第 j 列是新基矢在旧基下的坐标）；界面给对角矩阵。行列式不是正数时返回 `SupercellError`。
- 先按转为 P1 的方式展开，再对每个原子取 `x' = adj(M)·(x + n) / det M` 中落在 [−ε, 1 − ε)³ 内的像（ε = 10⁻⁹，每个新晶胞恰好一个），原子数恰为 P1 原子数的 det M 倍。adj(M) 的每一行先约去它和 det M 的公因数，所以对角矩阵就是除以该方向的倍数，坐标与手算的逐位相同（测试拿内置的 2×2×2 金红石超胞对照）。
- 对角矩阵把晶胞边长乘上倍数（不确定度一起乘），角度不变；其他矩阵经度规张量 `Mᵀ·G·M` 计算，余弦在舍入误差内是 0、±½ 的取精确值，角度在舍入误差内是整数度的取整数。晶格的朝向让原子在笛卡尔空间里不动（4.2 节，M10）。
- 标签：每个占位者的像按出现顺序编号为 `原标签_n`（如 Ti1_1 … Ti1_16），顺序是一个新晶胞接一个新晶胞。新位点 ID 从 1 起，空间群名称记为 P 1。
- 结果是新结构：界面把它作为派生结构加进同一项目（[项目文件设计稿](project-format.md) 7.2、13.2 节）。

### 7.10 对称性检测与对称化

- `DetectSymmetry` 是后台任务，在快照上运行。预览中显示：
  - 空间群和 setting
  - 不对称单元的位点数
  - 原子的最大位移
  - 是否改变晶胞或朝向（标准化）
- 用户确认后才提交 `Symmetrize`，它的逆操作就是恢复快照。

**M9 的实现**（`mw-crystal/src/symmetrize.rs`，命令在 `edit.rs`）：

- **检测**：`DetectSymmetry { symprec, standardize }::run(&Structure)` 是纯函数，在快照上运行，界面放在后台。它先把结构展开成每个原子一个位点（P1 结构原样使用，对称结构先转为 P1），按占位情况区分原子的种类：元素、氧化态、占位率（3 位小数）和无序组都相同才算同一种，P1 面板里"原子对称性"的检测（5.4 节）也改用这个规则。再经 `tables.rs` 交给 moyo 搜索，`symprec` 默认取结构自己的容差，可以由用户调；moyo 搜索失败时会自己逐步缩小容差。只检测到 P1（1 号）时拒绝（`NoHigherSymmetry`）。
- **只用 moyo 的近似结果定位**：moyo 给出类型和从当前晶胞到该类型标准设定惯用胞的 (P, p)。P 换成精确分数（分母不超过 1200，足以表示 1200 倍以内的超胞）；操作取表里标准设定的精确操作，不用 moyo 那组带浮点平移的。p 是原子决定的原点，可以是任意实数：在 24 分之一的格点 q 里找使 `o = p − P·q` 最短的（模结果的晶格平移，极轴方向的分量不计，因为沿极轴原点任意）；最短的 |o| 不超过容差时原点不动，原子在对称化中自己落到对称元素上，否则原点移到最近的对称性原点，操作仍取表列的那组（q 只在规范化子的平移里选，即 8 分之一和 6 分之一的格点，与 M8 相同）。所以从 P1 展开回来的结构保持原来的原点和设定，包括非标准设定和原点选择 1；随手平移过的 P1 结构则移动原点，预览会说明移了多远。
- **在一个"框架"里平均**：不标准化时框架是结构自己的晶胞，操作是 `P·W·P⁻¹`（只保留在这个晶胞的基下是整数矩阵的），平移是 `P·(w + (I − W)·q)`，再加上标准晶胞的晶格平移在这个晶胞里的像作为定心。超胞因此带着把各个小晶胞联系起来的纯平移；晶胞容纳不下全部对称性时（立方晶体的 2a × a × a 晶胞丢掉三重轴）只保留它容纳得下的子群，预览里写明检测到的类型和结果的类型不同，并提示标准化。标准化时框架是 moyo 给的标准惯用胞，操作就是表里的；原子经 `P⁻¹` 进来，晶胞比结构的大时每个原子按结构的晶格平移补成几份，比结构的小时几个原子落在同一处，先平均成一个。
- **平均**：框架里的原子按种类和框架的精确操作分成轨道。轨道的代表点取第一个原子，每个操作 g 把代表点送到某个原子 a(g) 附近（同种原子中最近的，距离不超过 4 倍容差），代表点的新位置是全部 `g⁻¹(a(g))` 的平均，它自动落在特殊位置上（位点对称群里的操作只是交换求和的项）。每个原子恰好被位点对称群那么多个操作送到，否则拒绝（`Mismatch`）。坐标经 M8 的 `tidy` 放回它在舍入误差内的分数或短小数上，所以 P1 展开再对称化逐位得到原来的坐标（落在 [0, 1) 内）；值没变的坐标保留不确定度。
- **合并成位点**：每个轨道一个位点，ID 取它第一个原子所在位点的 ID，顺序按第一个原子在原结构里的顺序。元素、氧化态和无序组取第一个原子的。占位率各原子都相同时原样保留（含不确定度），否则取平均、不带不确定度。位移参数各自经 `W_g⁻¹` 变回代表点（`transform_adp`，与 M5b 相同）再平均，所以结果满足位点对称性；只用与代表点同类（各向同性或各向异性）的；全都相同时保留代表点自己的值和不确定度。标签取第一个原子的；轨道里的标签恰好是转为 P1 时生成的 `O1_1`、`O1_2`……时取回 `O1`（与别的标签冲突时不取）。
- **晶胞**：度规张量按框架的点群平均（`symmetrized_metric`），所以 a = 3.905、b = 3.9051 的 P1 立方结构对称化后 a = b = c；参数经 `from_metric` 让直角和 120° 精确，没变的参数保留原值和不确定度。不标准化时朝向不变（左手系也照常保存，见下）。
- **标准化**：框架里的结果再用 M8 的规范化（`cell_transform::canonical`）在给出相同操作的等价惯用胞里选离标准朝向最近、原点平移最短的，经 M8 的换基（`change_basis`）换过去，位点坐标折回 [0, 1)。所以一个已经是标准惯用胞的 P1 结构标准化后晶胞不变，原胞和超胞得到标准惯用胞。没有经过 `Edit::TransformCell` 本身：M8 的变换要求新基矢是结构的晶格平移、体积变化在 8 倍以内，而 P1 超胞的小晶胞平移在对称化之前还不是"结构的晶格平移"，3×3×3 超胞的体积也差 27 倍；在标准惯用胞里直接平均就没有这些限制。
- **左手系**：先用 −a、−b、−c（`right_handed` 的同一变换）换成右手基再检测和平均；不标准化时再换回左手系，标准化的结果是右手系，预览说明朝向变了。对称结构的空间群类型（`SymmetryAnalysis`）对左手系晶格改为按 −a、−b、−c 识别，补上 4.2 节所说的缺口，P3₁21 和 P3₂21 不会认反。
- **检查**：结果按结构的 `position_tol` 展开，每个位点的原子数要等于框架里轨道的原子数。容差比位置容差小时，被对称性分开、但相距不到位置容差的两个原子会被展开合并，这时拒绝（`PositionTolerance`），提示把容差调到不小于位置容差。保持晶胞时操作超过 1536 个（Fm-3m 在 8 倍惯用胞里的数目）拒绝（`TooLarge`），提示标准化；标准化时框架里原子超过 20 000 个同样拒绝。原子在容差内对不上操作（`Mismatch`）、moyo 找不到对称性（`NotFound`，例如同种原子重叠，见第 11 节）、容差不是正数、没有原子，各有错误。已经有这些对称性的结构保持晶胞时拒绝（`NoHigherSymmetry`）。
- **预览**（`Symmetrization`）：结果结构、检测到的类型、结果的空间群类型（可能是子群）、原子的最大位移和移动最大的位点（笛卡尔距离，含晶胞的变化，不含原点的平移）、是否换了晶胞、朝向是否变了、原点移了多远。界面、能力注册表和命令得到的是同一个结果。
- **命令**：`Edit::Symmetrize { symprec, standardize }`，序列化成 `{"command": "symmetrize", "standardize": true}`，`symprec` 省略时用结构的容差。命令执行时再跑一次检测，结果与同一结构上的预览相同。逆命令 `RestoreAtoms { mapping, structure }` 放回整个结构，`mapping` 是从当前结构到放回结构的分数坐标仿射映射，供 7.11 节的最近原子映射使用；它的逆命令还是 `RestoreAtoms`，撤销和重做都逐位精确。`Structure.space_group` 记为结果的类型。
- **能力**：只读的 `structure.detect_symmetry` 给出预览，MCP Server 自动提供它；可撤销的 `structure.symmetrize` 执行（[AI 集成设计稿](ai-integration.md)第 4 节）。
- **测试**（`symmetrize.rs`）：v0.2 的验收测试取全部 530 个表列设定（两个一般位置的原子，一个带各向异性位移参数和坐标不确定度，再加一个特殊位置上的原子），每 5 个转一个朝向、每 7 个取左手系，展开成 P1、每个原子随机扰动不到容差的一半、对称化、再展开，原子位置在容差内不变，操作集、标签和位移参数逐项相同；另有平均、晶胞联动和不确定度的规则，原点不动、移动和极轴，标准化（fcc 原胞到 F 惯用胞、已经标准的不变），超胞保持晶胞或标准化、容纳不下的晶胞取子群、太大的晶胞只能标准化，种类区分（占位率、无序组），每种拒绝，选区和测量按最近原子映射与撤销重做，左手系，序列化。`mw-crystal-io/tests/symmetrize.rs` 用真实文件检查：P1 的岩盐 CIF、GaAs 的 POSCAR 原胞（标准化为 8 个原子的惯用胞）、硅的惯用胞（原点在原子上，即原点选择 1，原点不动），左手系 ZnO 对称化后经 CIF 写出再读回仍是 P6₃mc。
- **界面**：P1 结构检测到更高对称性时，属性面板对称性区域的"对称化…"和命令面板打开对话框（[界面设计稿](ui-shell.md) 第 5 节）：在后台检测、预览，可以改容差、选择标准化，确认后执行一步，可以撤销。

### 7.11 编辑后选区与测量的去向

每条命令 apply 之后，除了新结构，还返回一份 **ID 映射**：

- 未受影响的 Site：AtomRef 不变。
- 轨道大小改变的 Site（脱离或落到特殊位置）：它的 AtomRef 收缩为位点级的选择。
- 被删除的 Site：从选区中移除。
- `ExpandToP1`：给出旧 AtomRef → 新 SiteId 的完整映射，模式切换后选区和测量都能保留。
- `Symmetrize`：按最近原子映射。

测量的引用失效时，标记为"已失效"并保留，不静默删除。

**M5b 的实现**：`IdMap` 改为逐步记录（`Batch` 的每一步一层），新增两种去向：`Split`（转为 P1：成员 k 成为新位点 k 的唯一原子，晶胞偏移不变）和 `Merged`（撤销转为 P1：P1 位点的原子回到原位点的某个成员）。撤销用的 `RestoreStructure` 不知道是谁的逆操作，它把被替换结构里每个只有一个原子的位点，按位置逐位相同找到恢复后结构里的原子；转为 P1 再撤销时位置是同一次计算的结果，总能找到。选区里整个位点被拆开时选中拆出的全部位点；`IdMap::sites` 给出一个位点变成了哪些位点。

**M9 的补充**：对称化后的位点和原子与原来的不一一对应，所以按最近原子映射。去向 `Relocated` 记下原位点各成员的位置，以及与新结构共享的数据：从原结构到新结构的分数坐标映射（含换晶胞、换原点和左手系的翻转）和新结构的全部原子。`IdMap::atom` 把原子的分数坐标（成员位置加晶胞偏移）映射过去，取新结构里最近的原子和它所在的晶胞；`IdMap::sites` 给出位点的原子落在了哪些新位点上，按新结构的每个原子在原结构里最近的原子统计，所以撤销标准化时一个位点得到超胞里它的全部原子所在的位点。逆命令按反方向的映射同样找最近原子。

**M8 的补充**：晶胞变换后位点不变，原子换了成员号和晶胞偏移。去向 `Rebased` 记下仿射映射 `x' = P⁻¹·x − P⁻¹·p` 和变换前后各成员的位置；`IdMap::atom` 把原子的分数坐标（成员位置加晶胞偏移）映射过去，按位置找到新的成员号和晶胞偏移。晶胞变大时一个旧成员和它的旧晶格平移像会落到不同的新成员上，所以按位置找而不是按编号。选区、测量和正在拾取的原子都跟着原子走；撤销时用逆变换映射回来。

**M7 的补充**：移动位点（`MoveSite`、`SetCoordinate`、`SetPosition`、`RestorePosition`）后，比较移动前后生成各轨道成员的操作：完全相同时，成员编号指的还是同一个原子，引用不变；否则记为 `Reshaped`。所以沿特殊位置移动时选区和测量保留，离开或落到特殊位置（多重度变化），或移到同样大小但不同的特殊位置（如金红石从 4f 的 x, x, 0 到 4g 的 x, −x, 0）时，引用收缩为位点。成员的晶胞偏移不随移动调整：原子越过晶胞面时，同一个引用指向的是显示范围里留在晶胞内的那个像。拖动结束时，界面把被拖的原子（或收缩后的位点）设为选区。

**M4 的实现**：ID 映射是 `IdMap`，只记录被删除（`Removed`）和轨道大小变了（`Reshaped`）的位点；`IdMap::atom` 给出 `AtomFate`：不变、收缩为位点、或已删除。M4 的命令里，只有 `RemoveSite` 删除位点；改晶胞后，比较前后的轨道大小（位置容差以 Å 计，晶胞变化可能让等效原子合并或分开），变了的记为 `Reshaped`。界面的选区据此更新；文档里的测量引用到删除或收缩的原子时标为已失效。

### 7.12 撤销 / 重做

- 命令是可序列化的数据。`apply` 返回四样东西：新结构、逆命令、ID 映射、诊断信息。
- 批量命令（`ExpandToP1`、`Symmetrize`）的逆命令直接是"恢复快照 `Arc<Structure>`"。结构规模不大，快照比手写的精确逆操作更可靠。
- 撤销覆盖结构、标注和成键规则；不覆盖相机、配色、可见性和显示范围。
- 已提交的命令序列同时写入 `provenance.history`，可以导出成操作记录用于复现，以后也能用 Python 回放。

**M4 的实现**（`CrystalDocument::execute` / `undo` / `redo`）：

- 每条 `Command` 是一步：结构编辑（`Edit`），或添加、删除测量。新命令清空重做栈。
- 结构编辑的一步保存"撤销用的命令"和"重做用的命令"，两者互为逆命令：撤销时执行前者，得到的逆命令替换后者，反之亦然，所以撤销和重做都精确还原，不重新校验。
- 测量随每一步保存执行前后的列表（数据很小），撤销和重做直接换回，已失效的标记也随之恢复：删除位点再撤销，引用它的测量重新有效。
- 结果与当前结构完全相同的命令（例如再次输入原值）不产生一步；被拒绝的命令什么都不改。
- `history()` 给出已提交的命令，供来源记录（M6）使用；`undo_command()` / `redo_command()` 供界面显示"撤销 删除 O1"之类的说明。
- 撤销栈不限长度。
- 几何编辑（M7）：一次拖拽、一次坐标输入、一次添加各是一步；逆命令是 `RestorePosition`（原样放回位置和 s.u.）或 `RemoveSite`。撤销时界面不再显示这一步的警告和多重度通知，因为做这一步时已经显示过。
- 晶胞变换（M8）的逆命令同样恢复快照（`RestoreBasis`），另带逆变换，让引用跟着原子走（7.8、7.11 节）。
- 对称化（M9）的逆命令也恢复快照（`RestoreAtoms`），另带反方向的坐标映射，引用按最近原子跟回去（7.10、7.11 节）。
- **保存点**（M6）：每一步有文档内唯一的编号，`checkpoint()` 记下写出时栈顶那一步，写好后 `mark_saved(checkpoint)` 把它定为保存点（写的过程中又有编辑也不会被误标为已保存），`is_modified()` 比较当前栈顶，所以撤销回保存时的状态又是"未修改"；撤销过保存点再做新命令后，就只有继续撤销才回得去。`CrystalDocument::restore` 由项目文件里的结构和测量重建文档，没有撤销历史，引用不存在的原子的测量标为已失效（[项目文件设计稿](project-format.md)第 6 节）。

## 8. 校验与诊断

```text
Diagnostic { severity: Error | Warning | Info, code, message_key /* i18n */, target: Site | Occupant | SourceSpan }
```

| 级别 | 含义 | 例子 |
|---|---|---|
| Error | 硬约束，不可能构造出违反它的结构 | 度量张量非正定、操作集不封闭、占位率 ≤ 0、标签重复 |
| Warning | 允许存在，但用户需要知道 | 原子过近、占位率之和 > 1、晶胞参数与对称性不一致、电荷不平衡（有氧化态时） |
| Info | 程序替用户做过的修改，或用户需要知道的读法 | 吸附到特殊位置（附最大位移）、合并共占的行、对重复原子去重、左手系晶格、没有导入的 CONTCAR 速度 |

导入时产生的诊断带源文件行号，UI 可以直接跳到对应行。

标签重复和占位率 ≤ 0 是模型的硬约束，但导入时不让整个文件失败：重复的标签改名，占位率 ≤ 0 的行不导入，都给出警告（9.1 节）。

编辑（M4）不产生 Error 级诊断：违反硬约束的编辑直接被拒绝（`EditError`，见 7.2 节），结构不变。Warning 级的是 `EditWarning`：占位率之和 > 1 + 0.01、移动或添加后原子过近（`ShortContact`；自身的等效原子之间是 `CloseImages`，M7），随这一步的结果返回，由界面提示。Info 级的是 `EditInfo`（M7）：吸附到特殊位置的位移和多重度变化，界面合成一条信息通知，放在警告之上。

导出不改变结构，所以不产生诊断，只有两种结果需要告诉用户：

- **格式装不下结构**：POSCAR 和 XYZ 每个位置只能写一种原子，部分占位、混合占位和未知元素（`X`）都会让导出失败，返回 `ExportError`，列出涉及的位点标签。界面在选格式时就把这样的格式置灰并写明原因，不等到写文件。
- **CIF 少写了字段**：结构修改过后，源文件里未识别的字段不再写出（第 6 节），文件照常写出，并在通知里列出这些字段。

## 9. 导入与导出

### 9.1 CIF 导入流水线

1. **语法解析**：先支持 CIF 1.1（COD 的绝大部分文件是 1.1），保留行号。CIF 2.0 以后再加。
2. **语义解释**：
   - 处理新旧字段别名：`_symmetry_equiv_pos_as_xyz` ↔ `_space_group_symop_operation_xyz`，`_symmetry_space_group_name_H-M` ↔ `_space_group_name_H-M_alt`，等等。
   - 解析 s.u. 括号；区分 `?`（未知）和 `.`（不适用）。
   - Biso 换算成 Uiso；aniso loop 按标签关联到对应的原子行。aniso loop 给出 U、B 或无量纲的 β 都能读，依次优先 U、B、β：B 换算为 U = B / 8π²，β 用晶胞的倒格子长度换算为 U_ij = β_ij / (2π² a*_i a*_j)，不确定度按同样的系数换算，各给一条 Info。导出一律写 U。
3. **规范化**：
   - 校验操作集的封闭性，识别空间群。
   - 坐标相同、且没有 disorder 差异的行，合并为混合占位。
   - 靠近特殊位置的坐标吸附过去，并记录。
   - 对不对称单元中冗余列出的等效原子去重。
4. **生成文档**：每个 data block 生成一个文档（有多个 block 时让用户选），并附上导入报告。

**M1 的实现范围**（`mw-crystal-io`）：

- 第 1、2 步全部实现。另外：
  - 支持的字段别名：对称操作、H-M 符号、IT 号三组；同时出现且含义不同时用新名字并给出警告。操作按集合比较（顺序、大小写、写法不同都算相同），H-M 符号按所指的设定比较（`P 21/n` 与 `P 1 21/n 1` 相同，`F d -3 m` 与 `F d -3 m :1` 不同），其余忽略大小写和空格比较文本。
  - 没有 `_atom_site_type_symbol` 时从标签推断元素；认不出的符号按 `X` 保留并警告。
  - 文本块、单双引号字符串、重复字段、`save_` 帧（跳过）、非 UTF-8 文件都有对应的诊断。
  - 以下处理来自 COD 语料统计（11 节"默认容差"一行给出统计结果）：
    - 值全是 `?` / `.` 的原子行跳过，这是 COD 里没有坐标的条目。整个 block 没有带坐标的原子时报"没有原子位点"；晶胞也没有时按不含结构跳过（Info）。
    - 虚拟原子行（`_atom_site_calc_flag dum`）可以连标签都省略。
    - 标签重复（SHELXL-97 常把不同原子上的氢都叫 H1B）：后出现的改名为 `标签_n`，n 取文件里没用过的最小数字，给出警告；同名的各向异性行按出现顺序对应。
    - 占位率 ≤ 0 的行（精修到 0.00 的无序组分）不导入，给出警告，它的各向异性行一并丢弃。
    - s.u. 缺右括号（行在固定宽度处截断，如 `0.0029(18`）照常读取。位移参数不是数字时只给警告，忽略这一组位移参数；位移参数只为导出保留，不该因为笔误丢掉整个结构。
- 第 3 步只做了校验：
  - 操作集的封闭性按 4.4 节检查。
  - 空间群识别属于 M2，名称暂时直接取自文件。
  - 吸附到特殊位置、合并混合占位、冗余原子去重也要等 M2 的位点对称性。M1 只报告疑似情况：满占位位点的等效原子距离小于 `short_contact`、文件给出的多重度与展开结果不一致、两个位点位置重合。
- 文件没有列出对称操作时，4.4 节的 Hall > H-M > IT 号回退需要符号表（M2）。M1 只认 P1，其余报错。
- 第 4 步：有多个 data block 时，全部加入当前项目并打开第一个，由用户在边栏里选择，不另弹对话框；没有晶胞和原子位点的 block（如出版信息）跳过并给出 Info。
- 诊断是 `mw-crystal-io` 的 `DiagnosticKind`，带稳定的 `code()` 供语料统计；文字由界面翻译。编辑命令（M4）用自己的 `EditError` 和 `EditWarning`（第 8 节），导入诊断没有移到 `mw-crystal`；两者需要放进同一个列表（例如项目文件里的诊断记录）时再合并。

**M2 的实现范围**：

- 没有列出对称操作时按 Hall 符号 > H-M 符号 > IT 号生成，并给出 Info（P1 除外）。H-M 符号按完整符号匹配设定；简写符号、或没有 `:1` / `:2` / `:H` / `:R` 后缀时取标准设定（单斜 b 轴唯一、原点选择 2、六方轴）。Hall 符号里《国际表》B 卷的轴符号 `'`、`"` 先换成 moyo 的写法 `^`、`=`（`R 3 2"` 即 `R 3 2=`）。moyo 解析不了的 Hall 符号（带换基后缀的 `P 2yb (x,y,-x+z)`、不带空格的 `-P2yab`、畸形的 `-P 6C 2C` 等，见第 11 节）回退到 H-M 符号：调用 moyo 之前先按它的语法检查，调用时再用 `catch_unwind` 兜底。名称都认不出时仍是错误。
- 第 3 步全部实现，顺序为：
  1. **吸附**：`position_tol` 内有特殊位置的位点移到 5.4 节的平均位置上，不归一化到 [0, 1)。位移 ≥ 1×10⁻⁴ Å 时逐个位点给 Info，带行号、坐标形式和位移；更小的位移低于 4–5 位小数坐标本身的精度（如把 0.33333 读成 1/3），不报告。
  2. **合并与去重**：吸附后位置重合（`position_tol` 内，含等效位置）的两行，按文件顺序处理——disorder 组不同的保留为两个位点（Info）；都满占位且物种相同的是冗余列出，去掉后一行（Info）；都满占位但物种不同的保留并警告；其余合并为前一个位点的混合占位（Info），合并后占位率之和超过 1.01 时警告。
  3. 原有检查（等效原子过近、多重度不一致、原子过近）在整理后的结构上进行。多重度检查同时认三种写法：`_atom_site_symmetry_multiplicity` 按 ITA 的多重度；SHELXL-97 在同一个字段里写的却是位点对称阶 k = |操作集| / 多重度（一般位置为 1），一个 block 按更多数值吻合的那种约定解读；SHELXL-2014 以后写的 `_atom_site_site_symmetry_order` 也参与检查。不一致时报告文件给出或隐含的多重度。
- 识别操作集的空间群类型：文件给出的名称或 IT 号与之不符时警告；识别失败时警告。晶胞参数与操作集要求的晶胞相差超过 1×10⁻³（Å 或度）时警告（7.3 节）；更小的差别是打印位数造成的，比如 a = 32.2456(13) 旁边写 b = 32.246（11 节"默认容差"一行）。

### 9.2 CIF 导出

- 显式写出操作集（`_space_group_symop_operation_xyz`）；已识别空间群时，同时写出 H-M 符号、IT 号和 Hall 符号。
- 派生字段由模型重新生成；带 `su` 的值写出括号。
- **回归测试**：导入 → 导出 → 再导入，结构在容差内一致。用 COD 语料批量跑。

**M5 的实现**（`mw-crystal-io/src/cif_write.rs`，`cif::write` 返回文本，供 MCP 的 `structure.export` 直接使用）：

- **顺序**：`data_` 块名（取源数据块的名字，没有时由调用方给出，CIF 1.1 不允许的字符换成 `_`）→ 保留的描述性与未识别字段（第 6 节）→ 晶胞 → 空间群 → 对称操作 loop → 原子位点 loop → 各向异性 ADP loop。
- **空间群名称**：只写当前名字（`_space_group_*`），不写旧名字。操作集正是某个表列设定时，写 `_space_group_IT_number`、`_space_group_name_H-M_alt` 和 `_space_group_name_Hall`；H-M 符号在标准设定下用简写，非标准设定里有原点选择或菱方 / 六方轴之分的加 `:1`、`:2`、`:H`、`:R`，单斜的非标准设定用完整符号（如 `P 1 1 21/a`），其余用该设定的简写（正交的简写本身区分设定，如 `P b n m`）。只能经变换识别的设定（5.4 节）只写 IT 号：表列符号描述的是另一组操作。
- **派生字段**：`_cell_volume`、`_cell_formula_units_Z`、`_chemical_formula_sum`（Hill 顺序；各元素原子数都是整数时 Z 取它们的最大公约数，否则取各轨道大小的最大公约数，部分占位保留小数，如 `Ba0.5 O3 Sr0.5 Ti`）、`_space_group_crystal_system`、`_atom_site_symmetry_multiplicity`、`_atom_site_Wyckoff_symbol`（只在表列设定下写）。各向异性原子的 `_atom_site_U_iso_or_equiv` 写 Ueq，由写出的 Uij 计算，位数与 Uij 相同、最多 6 位小数。
- **数值**：
  - 从文件读来的数和不确定度按原来的小数位数写回，例如 `3.9475(3)`；判断方法是找最少的小数位数，使值和不确定度都是整数（最多 10 位）。
  - 不是有限小数的值（由 B 换算的 U、吸附后的 1/3）：带不确定度的按"19 规则"写，不确定度 10–19 写两位，其余写一位，值舍入到同一位；`(10)` 写成 `(1)`，因为它读回来就是这个意思。一位的不确定度舍入后进到 10 时同样处理，例如 0.000975 写成 `0.019(1)` 而不是 `0.0190(10)`，否则再导出一次文本就会变。舍入成零的值不带负号（`0.000(6)` 而不是 `-0.000(6)`），理由相同。不带不确定度的写 10 位小数。
  - 位点对称性固定的坐标不写不确定度，跟随其他坐标的照常写。不确定度为 0 写成 `(0)`。
  - 特殊位置上互相关联的坐标（一个跟随另一个）：读回时要靠它们的平均值吸附回同一个特殊位置，所以每个都至少写到这样的位数——舍入让原子移动不超过吸附容差的四分之一（按该轴的晶胞长度算），并且至少和它跟随的坐标一样精确。不确定度按同样的位数写，例如 `0.2312(100)`、`0.69376(50)`。没有不确定度的跟随坐标按它跟随的坐标的位数舍入。
  - 原子表和各向异性表里模型不保存的列，按导入器给每一行的最终标签保存：重复的标签改名后，列值跟着改名后的原子走；导入时跳过的行不保存。各向异性表的列只保留各向异性原子的值，因为只有它们会写出；没有值的列整列丢掉。
- **往返结果**：`tests/export.rs` 对每个测试文件做"导入 → 导出 → 再导入"，比较结构（数值在不确定度的一半以内，没有不确定度的在 10⁻⁹ 以内）、保留的字段，并要求第二次导出的文本与第一次相同、再导入没有新的错误或警告。`tests/cod_roundtrip.rs` 在 COD 语料上做同样的检查（默认忽略）。2026-10-23 的本地语料（504 373 个文件、503 216 个结构，即全部能导入的结构）**全部往返一致**。合并 COD 校准和导出两部分后，首次全量运行有 1 804 个不一致（99.64 %），逐类修复的原因依次是：重复标签改名后保留的列没跟着改名（1 781 个）；特殊位置上互相关联的坐标按各自的精度舍入，再吸附时平均值漂移（15 个），或偏离特殊位置超过吸附容差而读回时报原子与周期像过近（8 个）；一位不确定度舍入进到 10（13 个）；各向异性表的保留列在原子各向同性时留成空列（1 个）；舍入成零的值带负号（5 个）。规则见上面几条，每一类都有 `tests/export.rs` 里的最小复现测试。

### 9.3 POSCAR

**导入**：

- 支持缩放因子，负值表示目标体积。
- 读取 VASP 5 的元素行；VASP 4 没有元素行时，要求用户指定元素。
- Direct 和 Cartesian 坐标都支持；selective dynamics 标志在 v0.x 中忽略，并给出警告。
- 结果为 P1 结构，晶格朝向从基矢反算（4.2 节）：不在标准朝向的为 `Explicit`，按标准朝向写的为 `Standard`。

M10 的实现（`mw-crystal-io/src/poscar_read.rs`，`poscar::read` / `read_str` / `read_with_elements`）：

- **按行的位置读**，和 VASP 一样：注释行、缩放因子、三行晶格矢量、元素行（VASP 5）、原子数目、可选的 selective dynamics 行、坐标类型、每个原子一行坐标。每行只取需要的前几个数，后面的内容（selective dynamics 的 T/F、注释）不管。数接受 Fortran 的 `1.5D-3` 写法，不接受 NaN 和无穷。结果是一个"数据块"：名字取注释行，结构为 P1，不记空间群名称（文件没有写），占位率 1，标签按元素计数（Si1、Si2……，同一元素分两组列出时接着数）。
- **缩放因子**：一个正数乘到晶格和笛卡尔坐标上；负数是晶胞体积（Å³），按 `(|s| / |det A|)^(1/3)` 缩放。VASP 还允许三个数，分别作用于三个笛卡尔方向；三个相等时就是一个缩放因子，不相等时报错（`UnequalScaleFactors`）——这种写法很少见，而且没有在 VASP 文档上核对过它的确切含义，报错比猜错好。
- **晶格**：`Lattice::from_matrix`（4.2 节）从缩放后的矢量算出参数和朝向；矢量构不成晶胞时报错，左手系照常保存并给 Info（`LeftHandedLattice`，第 3 行）。按标准朝向写的矢量（a 沿 x，b 在 xy 平面内）读成 `Standard`，所以设计稿原来写的"结果为 `orientation = Explicit`"只对不在标准朝向的矢量成立。
- **元素**：第 6 行的第一个记号不是整数时是元素行（VASP 5），否则是 VASP 4 的数目行。元素名去掉第一个非字母之后的部分（POTCAR 后缀 `Fe_pv`、`Ti_pv/7b3a…`），首字母大写后认不出的按未知元素 `X` 保留原名并警告（与 CIF 相同）。VASP 4 文件报错 `MissingElements`，说明要给几种元素；`read_with_elements` 按数目行的顺序接受用户给的元素，界面里选择元素留到以后，现在的提示是让用户在文件里补上元素行。
- **坐标**：坐标类型行首字母是 C、c、K、k 时为 Cartesian（VASP 的规则），否则为 Direct；这一行本身是数字时说明它缺失了，报错。Cartesian 坐标先乘缩放因子，再用 `Lattice::to_fractional` 换成分数坐标；Direct 坐标原样保存，不归一化到 [0, 1)（第 3 节）。坐标行少于三个数逐行报错；文件在坐标读完之前结束时报告应有几行、实有几行。坐标之后还有内容（CONTCAR 的速度、预测-校正数据）时给 Info，不导入。
- **检查**：原子之间距离小于 `short_contact` 的报 `ShortContact` 警告，重合的原子也一样（距离 0.000 Å）。和 CIF 不同，POSCAR 每个原子都是文件明确列出的，所以不合并也不删除。
- 诊断全部带行号（文件在中途结束的除外），文字在界面的语言文件和 `mw-automation` 的英文说明里，与 CIF 的诊断相同。
- **测试**（`mw-crystal-io/tests/poscar.rs`）：`tests/fixtures/poscar/` 里 6 个手写的文件（VASP 5 Direct、fcc 原胞的 Cartesian 坐标与显式朝向、负缩放因子、带 POTCAR 后缀和 selective dynamics 与速度块的 CONTCAR、VASP 4、左手系）；每种错误和警告的行号；以及和导出器的往返：全部能写成 POSCAR 的测试结构、内置示例、非对角超胞和转过的、左手系的金红石（共 21 个）写出再读回，原子的元素和笛卡尔位置（差一个晶格平移）、晶格矢量、手性都相同，再写一遍文本逐字相同。

**导出**：

- 先展开为 P1。存在部分占位时阻止导出并说明原因：需要先有序化。
- 原子按元素分组，顺序稳定；使用 Direct 坐标。
- 晶格按 orientation 输出；注释行写入标题和来源。

M5 的实现（`mw-crystal-io/src/poscar.rs`）：

- 混合占位、占位率之和低于 0.99 的位点和未知元素都阻止导出（`ExportError`，见第 8 节）。
- 元素按在位点列表里第一次出现的顺序分组，组内按位点、轨道成员的顺序；坐标归一化到 [0, 1)，写 10 位小数，写出来会成为 1 的分量（如 0.99999999999）写成 0，同一个位置。缩放因子写 `1.0`。
- 晶格矩阵是 `Lattice::matrix`，即按朝向转过的 `R·A_std`（4.2 节，M10）；标准朝向的结构写出的和以前一样。
- 注释行由调用方给出，界面写"结构名 · 项目名"。界面建议的文件名用 `.vasp` 扩展名：VASP 要求的文件名是 `POSCAR`，但同一个目录里常要放多个结构，VESTA、ASE 和 pymatgen 都按 `.vasp` 识别。

**验证**（2026-10-23，复现命令见开发指南第 2 节）：本机没有 VASP，用生成 VASP 输入最常用的两个读取器核对：pymatgen 2026.10.16 的 `Poscar` 和 ASE 3.29.0 的 `ase.io.read(format="vasp")`。

- **样本**：示例程序 `export_atoms`（`mw-crystal-io/examples/`）把全部测试文件和内置示例的结构写成 POSCAR，旁边另写一份本 crate 的 CIF，共 24 个结构。其中 21 个写出，3 个因部分占位按上面的规则拒绝（`bst_su_aniso`、`rutile_near_special`、`zero_occupancy`）。写出的覆盖三斜（P-1，三个角都不是 90°）、单斜、六方、三方（R-3c，六方轴）、四方和立方，示例项目里的 2×2×2 金红石超胞，ZnO 的正交六方超胞（非对角矩阵），以及坐标贴近晶胞边界的 P1 结构。注释行和界面一样带非 ASCII 字符。
- **逐个核对**：
  - 按 VASP 读 POSCAR 的方式严格读一遍：缩放因子、三行晶格、元素行、数目行、首字母为 D 的坐标类型行、每个原子一行三个坐标；
  - pymatgen 读到的元素顺序和数目与位点给出的一致，晶胞参数相差在 10⁻⁷ 以内，坐标都在 [0, 1)；
  - ASE 读到的元素、晶胞和分数坐标与 pymatgen 相同；
  - pymatgen 按对称操作自己展开本 crate 写的 CIF，得到的原子与 POSCAR 一一对应（2×10⁻³ Å 以内）。
- **结果**：21 个全部通过。发现并修复一处：在 [0, 1) 内、但写成 10 位小数后成为 `1.0000000000` 的坐标，现在写成 0（最小复现测试是 `tests/export.rs` 的 `coordinates_that_round_to_one_are_written_as_zero`，扩展 XYZ 同样受影响）。VASP、pymatgen 和 ASE 本身都接受 1.0，受影响的只是假定坐标在 [0, 1) 的下游脚本。
- **与源文件对照**：再用 pymatgen 直接读原始测试文件，除两处外结构都相同。`alias_spellings` 的第二个数据块故意同时写了 `F d -3 m` 和 `F d -3 m :1`，导入器按现行字段取原点选择 2，得到金刚石结构的 8 个 Si；pymatgen 默认原点选择 1，得到 16 个。`corundum_hall` 只给 Hall 符号，pymatgen 不读 Hall 符号，按 P1 处理。两处都是对源文件的解读不同，与 POSCAR 无关。
- **没有覆盖的**：没有在 VASP 本身上运行过。

### 9.4 XYZ

- 支持扩展 XYZ（带 `Lattice="..."`）的导入和导出。
- 普通 XYZ 没有晶胞信息，只支持导出：笛卡尔坐标，P1 展开。

M5 实现了扩展 XYZ 的导出（`mw-crystal-io/src/xyz.rs`）：一帧，第二行是 `Lattice="a₁ a₂ a₃ b₁ b₂ b₃ c₁ c₂ c₃" Properties=species:S:1:pos:R:3 pbc="T T T"`，原子顺序和 POSCAR 相同，笛卡尔坐标（Å）写 10 位小数。基矢和坐标都在晶格的朝向里（4.2 节）。和 POSCAR 一样拒绝部分占位和未知元素。普通 XYZ 和扩展 XYZ 的导入还没有做。
